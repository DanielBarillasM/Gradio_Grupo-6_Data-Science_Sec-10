Definición

Tema principal

¿Qué es Gradio?

Un paquete open source que envuelve lógica de Python con una interfaz web interactiva.
  • Python primeroLa interfaz y la lógica viven juntas.
  • Sin frontend obligatorioNo exige JavaScript o CSS para comenzar.
  • Apache 2.0Proyecto abierto mantenido en GitHub.
  • Python 3.10+Requisito de la versión actual.
Arquitectura

El recorrido de una interacción

Una señal, cuatro estaciones.

Usuario

Cambia un filtro, escribe un texto o carga un archivo.

Componente

Dropdown, Slider, Image, Audio, Plot o Dataframe.

Función Python

Procesa datos, consulta una API o ejecuta un modelo.

Resultado

La interfaz actualiza texto, tabla, gráfica o multimedia.

evento → función → salida
Desarrollo

Tres niveles de abstracción

De una función simple a una app completa.

Interface

Envuelve una función con entradas y salidas. Ideal para el primer prototipo.

fninputsoutputs

RowColumnclickchange

ChatInterface

chatbotstreamingmultimodal
Sistema

Lo que ocurre detrás de la interfaz

Estado, cola y API integrados.

Eventos

click, change y load conectan gestos con funciones de Python.

Estado

Puede ser global, por sesión o persistente en el navegador según el caso.

Cola

Los límites de concurrencia protegen modelos pesados y recursos compartidos.

Clientes

Las apps pueden consumirse desde Python o JavaScript como endpoints programáticos.

Código

Hello World

Una interfaz en nueve líneas.

import gradio as gr

def saludar(nombre, intensidad):
    return f"Hola, {nombre}" + "!" * intensidad

demo = gr.Interface(
    fn=saludar,
    inputs=["text", "slider"],
    outputs="text",
)
demo.launch()
  1. Escribir una función normal.
  2. Declarar entradas y salidas.
  3. Ejecutar launch().
  4. Abrir 127.0.0.1:7860.

Balance

Decisión informada

Rápido no significa universal.

Lo que hace especialmente bien

  • Prototipa con muy poco código.
  • Acepta texto, imagen, audio, video y tablas.
  • Expone endpoints consumibles como API.
  • Facilita demostrar modelos de IA.

Lo que exige evaluar

  • Menor control visual que un frontend a medida.
  • Concurrencia y recursos en producción.
  • Autenticación, secretos y acceso a archivos.
  • Arquitectura para apps empresariales extensas.

Producción

Antes de publicar

Una demo pública también es un sistema.

Archivos

Limitar allowed_paths, bloquear rutas sensibles y controlar tamaños de carga.

Acceso

Añadir autenticación cuando los datos, modelos o resultados no sean públicos.

Concurrencia

Ajustar la cola y los límites por evento según CPU, memoria o GPU disponibles.

Operación

Registrar errores, fijar versiones, proteger secretos y probar bajo carga realista.

Conclusión

Criterio final

¿Cuándo elegir Gradio?

Cuando el valor está en la función o el modelo y necesitamos que alguien lo pruebe hoy.

Sí: demos, prototipos, enseñanza, IA y herramientas internas.

Evaluar: BI corporativo complejo, identidad visual rígida o gran escala.

Idea → experiencia compartible
